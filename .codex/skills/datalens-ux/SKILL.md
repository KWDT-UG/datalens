# Data Lens UX

Use this skill when shaping user flows, requirements, navigation, information architecture, interaction patterns, or usability reviews.

Read relevant material under `docs/ux/` and domain documentation before proposing changes. Start from the user’s goal, role, context, and decision they need to make—not from a screen or component.

For each workflow, clarify:

- entry point, user goal, and successful outcome;
- required information and hierarchy;
- system feedback, progress, empty, error, permission, and recovery states;
- discoverability, learnability, and keyboard/accessibility implications;
- behavior with real, incomplete, stale, or large datasets.

Keep interaction decisions explicit enough for UI, engineering, and QE to implement and verify. Do not prescribe visual styling or technical architecture unless it affects the user experience.

## Continuous improvement

Use usability findings, support feedback, analytics, research, and observed workflow failures as evidence for improvement. Record the user problem and evidence before changing guidance. Update this skill only when the pattern is repeatable and broadly applicable; keep one-off preferences, speculative ideas, and product decisions in the appropriate project documentation.
